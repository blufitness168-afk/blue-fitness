## Implemented

- Existing admin dynamic route dispatches scan to `r7_visit_action`, explicit IN/OUT (omitted direction remains IN for existing admin callers).
- Normal active ADMIN/OWNER authorization rechecked under SQL session/staff locks. Member row lock serializes IN/OUT. Partial unique index permits only one open visit/member.
- Actor-scoped request UUID/payload/result audit; same payload replay returns original result; changed direction/code/station with same key fails. Deterministic failures are recorded too: use a new request after business conditions change.
- IN delegates unchanged installed R3/R6 checkin logic. No new entitlement/points/money calculation. Already-open IN rejected before entitlement consumption. OUT closes only an open R7 visit, even if membership has expired since IN. No free-standing OUT, no implicit next-day close.
- Entry snapshot: selected PAID package JSON/order ID, main slot, used slot, active supplement ID/slot/expiry, admission reason. Welcome entries have no invented package and use existing welcome hours. No joins to current catalog to render visits.
- Snapshot/entry immutable; visit can transition once to paired exit; request audit cannot update/delete/truncate. Actor and server event time retained. Existing aggregate member expiry / latest-PAID admission semantics are inherited, not represented as a new provenance guarantee.
- Legacy checkins remain unchanged with null exit/snapshot and unknown duration. They cannot be closed by inventing an open R7 visit.
- History uses R7 entry event time, otherwise legacy checkin time. Offset-required datetime range `[from,to)`, UI explicitly sends Bangkok +07:00, 50 entries/page with stable timestamp/ID order. SQL aggregates all filtered entries, not current page, into 24 Bangkok hour bins (count entry events, not unique people/occupancy). Across multiple days, matching hours aggregate together. No pie chart (blocked R0).
- UI retains keyboard/USB BLU input and member name/code/phone search. Retry key retained after ambiguous errors and direction locked until response. No automatic write retries after unknown outcomes.
