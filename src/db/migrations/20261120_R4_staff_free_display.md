# R4 staff-free entitlement display — prepared, not deployed

- `/member` reads its own terms only for a normal MEMBER session. `/admin/members/[memberCode]` reads the resolved MEMBER detail target only as normal ADMIN/OWNER. The private SQL reader independently checks the hashed cookie's persisted session, mode, expiry, revocation, and caller role/status. It returns only package name, term dates, recorded Bangkok daily slot, and display status. There is no new HTTP endpoint and no sale/order ID, price, actor, reason, or finance history in the projection.
- Only unended terms appear. Before the start they are **Scheduled**, not a promise of future eligibility. During `[starts_at, ends_at)` the reader uses `admission_term` and the same PAID ordering as kiosk/frontdesk: **Active** if the helper proves that staff term, **Superseded** if a later online order takes precedence, **Blocked** otherwise. This is a read-only statement snapshot without an admission lock or slot gate. Active is not a claim of entry right now; the recorded slot is informational and check-in still evaluates its own gates. A page reload takes a new snapshot.
- Existing status/expiry are preserved and identified as legacy when the card is present. Staff dates do not replace or extend `members.expire_date`; online purchases and their history are unchanged.

## Installation and rollback (approval required)

Apply `20261120_R4_staff_free_display.sql` after the reviewed R4 foundation and admission migrations. The reader does not depend on or change the writer or finance reader. Keep `ENABLE_STAFF_FREE_DISPLAY` unset by default, including on installations missing the migration; the server skips SQL unless the value is `true`, and missing or unavailable reads leave the existing pages intact. This flag is independent of `ENABLE_STAFF_FREE` (writer).

The migration creates only a private `STABLE SECURITY INVOKER` function and revokes PUBLIC execute; it does not grant privileges. Review ACLs before enabling. Only the trusted server DB role should have private schema usage, execute on `display_terms` and its admission/R3 helper chain, and the required reads (`auth_sessions`, `members`, `free_sales`, `package_payment_orders`, `package_payment_point_ledger`, `payment_transfer_refs`). Do not grant to customer/staff DB roles. Rehearse the actual backend role and verify the deployed admission stack still uses the helper before enabling. To roll back display, unset its flag; if removing SQL, drop only `r4_staff_private.display_terms(text,text)`. Disable display before reverting admission. Retain all sale evidence.
