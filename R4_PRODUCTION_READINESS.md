## Operator invocation — schema only

From the repository root, during the authorized maintenance window:

```sh

```

Pass `--confirm-runtime-ready` **only after** verifying that the deployed settlement/app connection uses the pinned database and effective owner principal, all R4 writer flags are off, and live writers/background jobs plus competing schema/ACL changes are paused through postflight. The runner checks local `.env.local` and process flags but cannot inspect deployed runtime settings or enforce the pause. Missing confirmation or a conflicting configured writer flag blocks the run. Use the configured `DATABASE_URL` without an override and the existing Windows protected-snapshot and native PostgreSQL tools. No app deploy, flag write, cutover insert or provider action is part of this command.

A fresh snapshot, verified native recovery, full clone rehearsal and read-only live baseline guard are mandatory on every invocation. The runner records a protected `transaction-intent.json` before submission. `commitOutcome: unknown` means do not retry: reconcile the installed catalog and data/sequence invariants read-only against the protected intent and snapshot first. `committed` with a blocked postflight means the write returned success; investigate read-only, do not reapply. Keep writers paused until the state is reconciled. No schema design decision remains for this mode; the outstanding decision is whether the operator can attest to the runtime principal, disabled flags and maintenance pause.
